# 通过 SSH 采集远端用量

在“设置 → 多设备同步”中选择“通过 SSH 采集”，添加主机并保存轮询间隔。此模式会汇总本机和 SSH 主机的用量，不需要远端运行 Hub，也不需要让远端主动连接本机。

## 准备远端环境

远端需为 Linux 或 macOS，具备 POSIX Shell、Node.js 22.15 及以上版本（推荐 24 LTS），以及已安装生产依赖和扫描器的 Token Monitor 项目目录。Node.js 必须能在非交互 SSH 会话中直接运行。

```sh
git clone https://github.com/Javis603/token-monitor.git ~/token-monitor
cd ~/token-monitor
npm ci --omit=dev
npm run ensure:tokscale
```

先在终端运行 `ssh my-host 'node --version'` 检查环境。首次连接时，应在终端核对并信任主机指纹；应用不会自动接受未知或发生变化的主机密钥。

在“远端项目目录”中填写 `~/token-monitor` 或实际的绝对路径。应用每次通过 SSH 调用现有采集器：

```sh
cd ~/token-monitor && node src/agent/agent.js --once --dry-run --limits=false
```

应用不会在远端自动安装或更新软件。采集器按 SSH 用户的权限和配置读取工具数据，返回用量、估算费用、会话、项目和已启用的历史记录；本次调用关闭服务商额度查询，也不会向 Hub 上传。导入桌面前会沿用现有同步规则移除会话标题和对话文本；完整的全部历史会话明细也遵循 Hub 同步的省略规则。

## 配置连接

- **本机 SSH 别名**：填写本机 SSH 配置中的 `Host` 别名，系统 OpenSSH 会解析主机、用户、密钥、Agent 和 ProxyJump。轮询时不弹出密码或密钥口令提示；需要口令的密钥应先加入并解锁 SSH Agent。
- **账号密码**：填写主机、端口、用户名和密码。macOS、Linux 本机支持此方式；Windows 本机暂只支持别名、密钥和 Agent。
- **测试连接**：执行一次真实采集，耗时可能达到一次完整扫描的长度。测试成功后显示远端 Device ID；需要另点保存才会加入定时采集。

密码保存在现有主进程凭据文件 `credentials.json` 中，POSIX 权限为 `0600`。该文件是明文，不能防止同一系统用户下的其他进程读取。界面只接收“是否已配置”的状态；密码不会进入普通设置文件、SSH 命令参数、错误输出或同步数据。POSIX 上的临时 askpass 辅助脚本权限为 `0700`，只从 SSH 子进程环境读取密码，进程关闭后即清理。

编辑原连接时，密码留空会保留同一主机、端口和用户名对应的已有密码；修改这些字段后需要重新填写密码。清除已保存密码后，连接仍保留，等待填写新密码。

## 轮询和异常处理

轮询间隔支持 **15 秒至 24 小时**的整数秒，默认 **5 分钟**。启用 SSH 模式或修改配置后立即采集第一轮；多台主机按顺序采集，一轮结束后再等待配置的间隔。点“立即采集”可提前启动一轮，同时触发的刷新会合并。每次 SSH 操作最多等待三分钟，并限制返回数据量。

单次失败会保留内存中上次成功的数据，下一轮继续重试，并在对应主机旁显示错误。超过两倍轮询间隔未成功更新的设备会标为过期，最短判断窗口为十分钟。重启应用后重新采集；修改连接目标或远端目录会清除该连接的旧快照。删除连接会移除其统计和密码。

应用会拒绝重复添加同一个配置目标。不同别名如果指向同一远端用户的项目目录，也应只保留一个，避免重复统计。

切换同步方式或退出应用会取消正在运行的 SSH。若强制终止后仍无法确认进程已关闭，应用会停止启动新的 SSH，重启后恢复；其他同步方式仍可使用。每个连接具有独立的设备标识，避免远端和本机同名时互相覆盖。
