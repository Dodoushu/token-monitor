# 通过 SSH 采集远端用量

在“设置 → 多设备同步”中选择“通过 SSH 采集”，添加机器并保存轮询间隔。此模式会汇总本机与各 SSH 连接最近一次成功采集的用量，不需要远端运行 Hub，也不需要远端主动连接本机。

## 远端要求和采集范围

远端 Linux/macOS 主机需要已有 SSH 服务、系统命令 `sh`、`find`、`tar`，以及会话文件的读取权限。若远端有 `gzip`，传输时会压缩数据。应用不会在远端安装软件，也不要求远端具备 Node.js、Python、npm、Token Monitor 或扫描器。

“远端用户目录”为选填项，默认 `~`，使用 SSH 用户的 `HOME`。只有日志位于另一个可读取的用户目录时，才需要修改。旧版“远端项目目录”的值不会自动转为用户目录。

远端命令只选择固定白名单内的普通会话文件，支持 Claude Code、Codex、Kimi、Droid、Qwen、Gemini、OpenClaw、Pi、Grok、Command Code、CodeBuddy 和 DSH 等来源。SSH 采集支持的是桌面应用工具列表的一个子集，暂不支持 OpenCode 等实时 SQLite 数据库。服务商认证文件、通用应用配置、Cookie、私钥和任意项目文件均不在白名单内。

会话日志可能包含提问和回复。选中的文件通过 SSH 传回本机解析；SSH 模式不会把它们发送到 Hub。每次采集使用新的本机临时 HOME，POSIX 权限为 `0700`。解包前会校验路径、文件类型和链接，并限制传输大小、解压大小和文件数量。归档不安全或不完整时，采集失败，不发布新数据；成功、失败或取消后，都会在 `finally` 中删除临时镜像。

## 配置连接

先在终端连接一次，例如运行 `ssh my-host`，核验主机指纹。应用不会自动接受未知或发生变化的主机密钥。

- **本机 SSH 别名**：填写本机 SSH 配置中的 `Host` 别名，系统 OpenSSH 会解析主机、用户、密钥、Agent 和 ProxyJump。轮询不弹出口令提示；需要口令的密钥应先加入并解锁 SSH Agent。
- **账号密码**：填写主机、端口、用户名和密码。macOS、Linux 本机支持此方式；Windows 本机暂只支持别名、密钥和 Agent。
- **测试采集**：执行一次真实传输和本地扫描，不保存草稿；另点保存才会加入轮询。测试成功后显示远端 Device ID。

密码保存在现有主进程凭据文件 `credentials.json` 中，POSIX 权限为 `0600`。该文件是明文，不能防止同一系统用户下的其他进程读取。界面只接收“是否已配置”的状态；密码不会进入普通设置文件、SSH 命令参数、错误输出或用量记录。POSIX 上的临时 askpass 脚本权限为 `0700`，从 SSH 子进程环境读取密码，进程关闭后清理。

编辑原连接时，密码留空会保留同一主机、端口和用户名对应的已有密码；修改这些字段后需要重新填写密码。清除密码后，连接仍保留，等待填写新密码。

## 本地统计与轮询

本机自带的扫描器只读取已经完整接收的临时镜像。每次调用都显式指定 `--home` 和非空的 `--client` 白名单，使用清理后的环境变量，并把临时镜像设为工作目录。今日、本月、全部历史和历史图表按顺序扫描，日、月边界使用本机时区。本次采集不查询服务商额度，也不使用服务商账号凭据。导入界面的用量记录沿用现有同步规则，移除会话标题和对话文本。

目前每次轮询都会完整读取白名单内的远端会话文件，尚未实现增量传输。日志较多时，首次测试或采集可能较慢。传输和本地扫描各有超时限制，不完整的扫描会报错，不会作为部分成功发布。

轮询间隔支持 **15 秒至 24 小时**的整数秒，默认 **5 分钟**。启用 SSH 模式或修改配置后立即开始一轮；多台机器按顺序采集，一轮结束后再等待配置的间隔。“立即采集”可提前启动一轮，同时触发的刷新会合并。

单次失败会保留内存中上次成功的数据，下一轮继续重试，并在对应机器旁显示错误。超过两倍轮询间隔未成功更新的设备会标为过期，最短判断窗口为十分钟。重启应用后重新采集。修改 SSH 连接目标或远端用户目录会清除对应旧快照；移除连接会删除其统计和密码。不同别名若指向同一远端用户的日志，应只保留一个，避免重复统计。

切换同步方式或退出应用会取消 SSH 传输与本地扫描。替换采集进程前必须确认旧进程已关闭。若强制终止后仍无法确认关闭，应用会停止启动新的 SSH，重启后恢复；其他同步方式仍可使用。每个连接具有独立设备标识，避免远端与本机同名时互相覆盖。
